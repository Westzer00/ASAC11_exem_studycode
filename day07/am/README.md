# RAG Evaluation
## RAG 구조와 실패의 종류
```
질문
  ↓
문서 검색
  ↓
검색된 Chunk
  ↓
LLM 답변 생성
  ↓
근거 인용
  ↓
최종 형식 출력
```
| 단계         | 대표 실패    |
| ---------- | -------- |
| 문서 검색      | 검색 실패    |
| 답변 생성      | 생성 실패    |
| Context 활용 | 근거 사용 실패 |
| 출처 표시      | 인용 실패    |
| 최종 출력      | 답변 형식 실패 |

### 확인해야 되는 사항
1. 검색 결과에 정답 근거가 있었는가?
2. 모델이 그 근거를 사용해 올바르게 답했는가?
3. 답변의 근거와 형식이 정확했는가?
## 평가에 이용될 문서
document.json 사용
### 요소
* 명확한 사실
* 여러 문서에 나뉜 정보
* 날짜와 숫자
* 표현이 서로 다른 유사 문장
* 이름이나 제품이 비슷한 문서
* 문서에 존재하지 않는 정보
### 구성
| 질문 유형           |      개수 |
| --------------- | ------: |
| 문서에 답이 명확히 존재   |      4개 |
| 여러 Chunk를 봐야 함  |      4개 |
| 문서와 표현이 다름      |      4개 |
| 숫자·날짜 포함        |      4개 |
| 답이 문서에 없음       |      4개 |
| 비슷한 문서가 여러 개 존재 |      4개 |
| **합계**          | **24개** |

## 실패 유형 결정
result.csv로 저장
```
1. 정답 근거가 검색 결과에 있는가?
   └─ 없음 → 검색 실패

2. 정답 근거는 있는데 답변이 틀렸는가?
   └─ 맞음 → 생성 실패

3. 필요한 Context 일부를 사용하지 않았는가?
   └─ 맞음 → 근거 사용 실패 or Context Utilization 실패

4. Context에 없는 주장을 추가했는가?
   └─ 맞음 → Faithfulness 실패

5. 답변 내용은 맞지만 잘못된 Chunk를 인용했는가?
   └─ 맞음 → 인용 실패

6. 내용은 맞지만 요구 형식을 지키지 않았는가?
   └─ 맞음 → 답변 형식 실패 
```
