# 1. 목적

본 문서는 프로젝트 생성부터 종료까지의 운영 절차를 정의한다.

모든 프로젝트는 본 매뉴얼을 따라야 한다.

--------------------------------------------------

## 2. 프로젝트 생성

새 프로젝트는 프로젝트 관리자(Project Manager, PM)가 Jira에서 생성한다.

프로젝트 생성 시 프로젝트명, 담당 부서, 일정, 참여 인원을 등록해야 한다.

프로젝트 생성 권한은 PM에게만 부여된다.

--------------------------------------------------

## 3. 요구사항 관리

기능 요구사항은 Jira Issue로 등록한다.

모든 변경 사항은 Issue를 통해 관리한다.

긴급 수정도 반드시 Issue를 생성해야 한다.

--------------------------------------------------

## 4. 개발 절차

개발자는 GitLab에서 개인 브랜치를 생성한다.

기능 개발이 완료되면 Merge Request(MR)를 생성한다.

최소 한 명 이상의 코드 리뷰를 받은 후 병합(Merge)할 수 있다.

직접 main 브랜치에 코드를 반영하는 것은 허용되지 않는다.

--------------------------------------------------

## 5. 문서 작성

프로젝트 설계 문서와 회의록은 Confluence에 작성한다.

API 명세와 운영 매뉴얼도 Confluence에서 관리한다.

문서는 최신 상태를 유지해야 한다.

--------------------------------------------------

## 6. 테스트

기능 개발 후 단위 테스트(Unit Test)를 수행한다.

주요 기능은 통합 테스트(Integration Test)를 수행한다.

테스트 결과는 Jira Issue에 첨부한다.

--------------------------------------------------

## 7. 프로젝트 종료

프로젝트 종료 전 회고(Retrospective)를 진행한다.

회고 결과는 Confluence에 기록한다.

프로젝트 종료 보고서는 PM이 작성한다.

--------------------------------------------------

## 8. 프로젝트 권한

프로젝트 생성 권한 : PM

Issue 수정 권한 : 담당 개발자

Merge 승인 권한 : Reviewer

프로젝트 종료 승인 : 개발팀장

--------------------------------------------------

## 9. 관련 시스템

프로젝트 관리 : Jira

소스코드 관리 : GitLab

문서 관리 : Confluence

원격 접속 : VPN

시스템 접근 정책은 IT System Guide를 따른다.
